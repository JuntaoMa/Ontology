02 / VALIDATOR CONTRACT

校验器是可编排的判定契约

每个节点都必须声明身份、作用域、输入、判据、执行、结论、权限、证据和成本；只有契约完整，校验器才能被安全复用与编排。

INPUT CONTRACT 制品 + 配置 + 前置输出 内容哈希固定，依赖显式声明
Validator ID · Version SCOPE

原子校验器 Atomic Validator

判据 × 执行引擎 → 可解释结论

V / S / A / H Cost Budget
OUTPUT ENVELOPE Verdict + Finding + Evidence 稳定 ID、指标、诊断与修复草案
SCOPE MODEL

作用域决定结论能覆盖多大边界

03 / RELATION MODEL

校验器之间不是简单先后关系

依赖边必须表达语义：谁提供输入、谁构成门禁、谁只负责解释、哪些依赖按制品条件激活，以及何时升级到人工复核。

04 / DAG ORCHESTRATION

以 DAG 组织执行，而不是写死流水线

manifest 决定本次运行需要哪些节点；编排器按依赖拓扑调度、并行扇出、门禁传播、结果扇入，并把人工批准建模为显式节点。

RUNTIME POLICIES

05 / COVERAGE MAP

校验覆盖链路

这里表达校验范围而非固定执行顺序；实际运行顺序由上方 DAG、manifest 与条件依赖共同决定。

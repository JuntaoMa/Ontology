Landscape

01 · 研究全景：问题不是一个“更好的 Top‑K”

相关工作已经形成六条相互独立但可组合的技术线：锚点识别、层次/图结构扩展、形式本体模块抽取、上下文编译、查询计划生成与形式验证、Agent 自适应检索。它们的训练信号与评测对象明显不同。

自然语言 → 本体锚点

精确/模糊词法、dense embedding、relation-first reranker、domain/range 与类层次导航共同完成 class/property linking。近期证据显示：类名通常较容易向量链接，关系/属性更依赖结构约束。

ANCHORSG-KBQAGenOM

锚点 → 相关结构

候选扩展包括 k-hop、最短路径、PCST、PPR、独立 triple scoring、hyperedge set cover、双曲层次重排，以及 OWL locality module。不同算法优化的目标并不相同。

G-RetrieverSubgraphRAGOWL module

结构 → Agent 上下文

召回结构需要被编译为 schema card、路径、Manchester Syntax、公理解释、可调用工具与预算化文本。完整 schema 直接入 prompt 仍常见，但大型本体下缺少系统 benchmark。

Progressive revealOntoSCPromptKAG

上下文 → 查询计划

主流路线包括 logical-form sketch、S-expression、SPARQL/Cypher、受约束 DSL 和工具计划。把结构先确定、内容后绑定，通常比一次性生成完整查询更可控。

ChatKBQATIARAPangu

计划 → 形式验证

本体不仅是生成上下文，也可以作为静态检查器：domain/range、属性存在性、类型兼容、SHACL cardinality/datatype，以及 reasoner consistency 均可给出确定性反馈。

OBQCSHACLROBOT/Jena

固定流水线 → 自适应 Agent

新的系统用 reader feedback、RL、调用成本和检索进度奖励学习“何时检索、检索几次、保留多少证据”。但多数训练和评测仍发生在 ABox QA，而非大型 OWL TBox。

GraphRAG-R1GRILHyperGraphPro

当前领域最明显的断层：经典本体工程可以围绕 signature 抽取保持特定蕴含的 locality module；现代 GraphRAG 可以从自然语言学习 relevance。二者如何结合、如何在大型 TBox 上同时评测“语义保持、相关性、token 成本和最终答案”，仍缺少被广泛采用的公开基准。
Terminology audit

02 · 论文中的“Ontology / Graph”至少有四种含义

这是理解文献结论能否迁移到本项目的首要条件。同样写着 ontology-guided 或 GraphRAG，实际处理的语义对象可能完全不同。

类型典型内容代表工作能否表达形式语义与本项目 TBox 的关系
标准逻辑本体
OWL / DL / SHACL		 class、object/data property、subsumption、domain/range、restriction、disjointness、公理和蕴含 DL-Lite 研究、Progressive Reveal、ANCHOR、OBQC、RIGOR、OWLAPI 是，可由 reasoner/validator 解释 直接相关；可以研究公理级上下文、模块与合法性。
轻量 taxonomy / type schema is-a 层次、实体类型、关系 domain/range，有时带描述和同义词 HyEm、ORT、OntoTune、TaxoLLaMA、KAG concept graph 部分；通常无复杂 restriction/逻辑闭包 适合研究术语链接和层次扩展，但不能替代 OWL 推理。
文档抽取模板 / 事实 schema LLM 从文档抽出的实体、关系、subject–attribute–value 或 hyperedge OG-RAG、Microsoft GraphRAG、LightRAG、HippoRAG 通常否 可借鉴检索算法和上下文预算；不能直接证明 TBox 召回能力。
ABox / 属性图 具体实体及事实边；schema 多为 node/edge label 约束 G-Retriever、SubgraphRAG、ToG-2、BYOKG-RAG、Neo4j GraphRAG 依系统而定，常为 LPG schema 更接近未来实例查询；当前黑盒阶段主要作为算法对照。
最常见的误读：WebQSP / ComplexWebQuestions 上“答案实体命中提高”，不能直接推出 OWL class/property/axiom 的召回更完整；文档图的社区摘要也不能保证保留 someValuesFrom、property chain 或 disjointness 等形式语义。
Problem decomposition

03 · 从问题到答案：可被独立研究的七个阶段

1 · 问题解析意图、实体 mention、关系短语、约束、输出目标
2 · 锚点链接class/property/individual 候选与方向消歧
3 · 结构召回路径、扩散、Steiner、模块、公理与说明文档
4 · 上下文编译schema card、可用关系、约束、来源和 token budget
5 · 计划生成logical form、SPARQL/nGQL/Cypher 或工具参数
6 · 查询执行实例引擎可内置，也可以完全黑盒
7 · 答案生成证据绑定、解释、缺失信息与不确定性

现有研究最密集处

  • ABox 实体链接、relation/path retrieval 与 answer entity recall。
  • 文档抽图后的 PPR、社区、图路径和混合 passage retrieval。
  • schema-aware logical form / SPARQL / Cypher 生成。
  • 检索—阅读联合训练和 Agent 多轮工具调用。

公开证据仍稀疏处

  • 大型 OWL TBox 的 query-specific axiom/module retrieval。
  • class、object property、data property 分角色的 Recall@K。
  • 模块是否保持 competency question 所需蕴含。
  • 本体层召回与黑盒 ABox 查询的端到端归因评测。
Evolution

04 · 技术演进：形式模块、语义解析与 Agent GraphRAG 正在汇合

2008—2021 · 形式本体基础

Locality module、verbalization 与 ontology embedding

OWL module extraction 以 seed signature 为起点保存特定蕴含；NaturalOWL 研究可读 verbalization；OPA2Vec、OWL2Vec* 把标签、公理与图 walk 编码为向量。它们分别解决语义保证、可读表达和候选相似性。

2022—2023 · Schema-aware KBQA

TIARA、Pangu：先约束结构，再让模型生成

检索实体邻域、关系和 schema，生成可执行 logical form；“模型不是独自记住整个 KG schema”成为主流设计。

2024 · GraphRAG 算法与本体校验分化

G-Retriever、ToG-2、ChatKBQA、OBQC、Progressive Reveal

一边用 PCST、图文混合和结构化 logical form 提高 ABox QA；另一边开始把企业 OWL ontology 作为渐进上下文服务或查询校验器。

2025 · Schema-first、联合训练与 Agent 检索

SG-KBQA、SubgraphRAG、OG-RAG、KAG、GRIL、GraphRAG-R1

relation-first schema linking、独立 triple scoring、hyperedge cover、逻辑形式规划、reader-aware graph retriever 和 RL 检索控制同时出现。

2026 · 大型层次检索与闭环 mapping

ANCHOR、HyEm、HyperGraphPro、Ontology-Guided Agent Memory

前沿预印本开始把任意大 schema 的层次导航、双曲结构、SHACL 闭环和 step-wise retrieval reward 纳入统一流水线；但大多仍待更多公开数据和独立复现。

Can LLMs Understand DL‑Lite Ontologies?

Findings of EMNLP 2024 · 代码与数据
同行评审真本体全文深读

研究设计

作者没有把普通 KGQA 当作“理解本体”的替代指标，而是直接构造 DL‑Lite TBox/ABox 任务：语法识别、概念 subsumption、instance checking、逆关系/函数性质、查询回答与 satisfiability，并用 Protégé/HermiT 产生或核验 gold。

关键实验：在 LUBM 上把 ontology 拆成 10 个 chunk，依次给 GPT‑4o，再要求回答 14 个查询；同时扩大 UOBM ABox，从 466 assertions 增长到 2,338，观察规模阈值。

结果与含义

  • 局部语法任务中 GPT‑4o 常达到 88–100%。
  • 超过规模阈值后，一些任务接近 0%；性能并非平滑下降。
  • LUBM 的 14 个集合查询中，顺序读完 10 个 ontology chunk 后仍没有一个完全正确。
  • 对 negative inclusion 的传递性存在系统性错误；MaasMatch satisfiability 上 GPT‑4o F1 约 69。
证据边界：它证明 LLM 能处理小而局部的本体片段，却不支持“把完整本体逐段塞入上下文即可替代 reasoner”。这是本报告中反对 full-schema prompting 外推最直接的实验。

Progressive Ontology Reveal：逐步披露企业本体

arXiv 2024 · 工业 telecom 案例 · 5 页短文
预印本真本体全文深读

系统机制

  1. Approximation：只给非正式自然语言 schema，让 LLM 尝试形成查询。
  2. Refinement：LLM 若缺少类或连接关系，显式返回 missing concepts/links。
  3. Ontology service：围绕这些项扩展 ontology slice，再交回 LLM。
  4. Termination：missing 为空，或两轮切片无变化时停止。
  5. Translation：最终生成 SPARQL 并执行。

工业图约含 500 concepts、1,000 relations、>7,000 OWL axioms，实例数据为数十 TB。它没有使用向量数据库，核心是“LLM 声明缺口 + 确定性 ontology service 缩小上下文”。

这篇工作的重要性与不足

它直接回答了“本体太大不能全塞 prompt”时的交互协议问题：Agent 不需要掌握全部 ontology，只需知道如何表达缺失的 schema 信息，并让外部服务控制披露范围。

证据很弱：作者仅称“绝大多数”查询取得良好结果，没有公开问题数、execution accuracy、token、延迟、slice size 或对照组；系统与数据也未公开。因此它是很有价值的工业设计模式，不是已充分验证的算法结论。

ANCHOR：Embedding 候选 + 层次导航 + SHACL 闭环

arXiv 2026 · Cyber Threat Intelligence ontology mapping
2026 预印本OWL / SHACL全文深读
Schema 初始化解析 class/property、description、hierarchy 与 SHACL
Schema-free 抽取mention、type hint、属性和三元组
Class embeddingname + description 候选，阈值接受
Hierarchy recurse低置信时由 LLM 从 root 向 child 导航
Property routing区分 data/object，使用 domain/range/direction
Scoped rerank只在选中分支内再次 embedding
SHACL repair验证并反馈，最多 3 轮

精确技术细节

entity_score = 0.5 · sim(type_hint, name) + 0.5 · sim(type_hint, description) + keyword_bonus(0.3) accept if score ≥ τ_entity = 0.45 predicate mapping uses τ_pred = 0.30 direction bonus: +0.10 forward / −0.05 inverse

系统暴露六个 search/navigation 工具，不把完整 schema 放进 prompt。predicate 先按 data/object property 分流，再把继承的 domain/range 与 SHACL shape 用作结构约束。

数据与结果

149 篇 CTI 报告；UCO 有 419 classes / 177 relations / 578 properties，STIX 为 109 / 92 / 311，MALOnt 为 75 / 10 / 12。

  • entity F1：ANCHOR 平均 .7371；对比 LLM4CTI 平均约 .6433。
  • predicate F1：平均 .5484。
  • 给定 gold typing 后，hybrid class/property F1 为 .9364 / .7843。
  • search-only 对 property 仅 .3142；recurse-only 为 .6416。
  • UCO schema noncompliance 为 5.2%，对照方法为 43.9–75.8%。
最有价值的观察：91% 的 entity mapping 可由 search 路由完成；object property mapping 则 72.1% 走层次递归。中位 top‑1 similarity 从 class 的 .837 降到 object property 的 .244。类通常是词法问题，关系更像结构问题。局限是预印本、CTI extraction 而非 QA、gold 部分由 LLM 辅助、代码尚未公开。

Ontology‑Based Query Check：把 ontology 当静态检查器

2024 · 企业保险 ontology · Text-to-SPARQL repair

实现方式

系统解析 SPARQL basic graph pattern，把 query variables 替换成 reserved IRI nodes，分别放入 :query 与 :ontology named graph，再执行一组 SPARQL 规则。检查项包括 property 存在性、domain、range、double-domain、double-range 与 domain-range compatibility。

repair prompt 只包含错误查询和检查器返回的问题说明，最多修复 3 次；不是把全部 ontology 再送回 LLM。

执行准确率

  • 首次生成：42.88%
  • OBQC + repair：72.55%
  • 正确返回 unknown：8%
  • 最终错误：19.44%

在“低问题复杂度 / 高 schema 复杂度”象限中从 17.20% 提升到 76.33%，显示校验在复杂 schema 下作用最大。

HyEm：普通向量索引上的双曲本体层次召回

arXiv 2026 · HPO / DO / MeSH · is-a hierarchy retrieval
2026 预印本真实 biomedical ontology

方法

在 Lorentz 双曲空间学习带 radius constraint 的 node embedding，通过 origin log-map 投影到普通 Euclidean ANN 索引；候选集上再计算精确双曲距离。轻量 gate α(q) 依据 entity-centric、taxonomy-navigation、mixed intent 混合 cosine semantic score 与 hierarchy score。

结果

  • 20k-node 子集，Euclidean MRR retention：.959 / .964。
  • Parent Hits@10：.226 / .310；mixed Hits@10：.449 / .361。
  • ANN oversampling L=50 时，hyperbolic top‑10 recall 为 .988 / .989。
  • CPU 查询延迟约 .596 / .544 ms。
边界：查询由合成模板构造，主实验只到 5k/20k 子集，仅处理 is-a，没有下游 LLM QA，也不表达复杂 OWL restrictions。它提供“层次感知候选层”的前沿证据，不是 reasoning layer。

同一技术线上的其他工作

RIGOR：检索增强的 OWL ontology 迭代生成

按 foreign-key 连通顺序逐表生成 Manchester Syntax delta；同时检索 DB schema/docs、外部 BioPortal ontology 与持续增长的 core ontology，Judge LLM 检查后合并并记录 provenance。两个医疗数据库上，多模型 competency-question 分数大致从 1.4–1.6 提升到 4.5–4.6 / 5，所有 RIGOR 结果 syntactically valid 且 consistent；但评价大量依赖 Judge LLM，OOPS 仍发现多个 domain/range 问题。

GenOM：结构 verbalization 后再做 ontology matching

从 label、synonym、immediate parent 和 EquivalentClass 提取上下文，用 DeepOnto verbalize，LLM 生成 richer definition；embedding top‑k 后让 LLM 判等价，再融合 cosine 与 exact lexical match。它把“只嵌标签”扩展为“标签 + 同义词 + 层次 + 公理 verbalization”。

OntoTune / TaxoLLaMA：把 taxonomy 部分参数化

OntoTune 从 SNOMED CT definition/hypernym/synonym 生成 ontology-informed response，再用 SFT/DPO 自训练；TaxoLLaMA 用 WordNet instruction tuning 学 taxonomy enrichment 和 hypernym discovery。它们探索“让模型先学会部分本体结构”，但尚无证据能替代动态检索或 reasoner。

Ontology-based RAG for Maintenance

在 OWL 维护本体上比较 label matching、vector semantic matching 与 graph traversal neighbor expansion，并用多 LLM、多上下文大小和 pairwise arena/Elo 评价回答。论文支持“向量 + 经典匹配 + ontology 邻域”的组合，但公开摘要不足以证明大型 module extraction 的规模表现。

Graph / subgraph retrieval

07 · 子图召回：连通、扩散、独立打分与超图覆盖并无统一胜者

这些算法大多在 ABox 或文档图上提出，但它们明确展示了可供 TBox 候选层借鉴的不同目标函数。尤其需要避免把“最小连通”视为天然语义最优。

G‑Retriever：Prize‑Collecting Steiner Tree

NeurIPS 2024 · graph QA · Llama‑2‑7B + graph token
同行评审全文深读

SBERT 分别编码 query 与 node/edge text，将相似度转为 prize；PCST 在连接成本和证据相关性之间求解小子图。edge prize 通过 virtual node 转换，使 node/edge 可以统一优化。

S* = argmax_S [ Σ(v ∈ V_S) prize(v) + Σ(e ∈ E_S) prize(e) − Σ(e ∈ E_S) cost(e) ]

检索子图既序列化为文本，也经 GNN 编码成 graph token 注入 LLM。

  • WebQSP prompt-tune：48.34；GraphToken：57.05；G‑Retriever：70.49；LoRA：73.79。
  • 平均 nodes：1,371 → 18；tokens：100,627 → 610。
  • 每 epoch：18.7 → 6.2 分钟。
  • k=3/5/10/20：.6977/.7063/.7248/.7039，更大上下文并不单调更好。
PCST 保证结构连通和预算平衡，不保证 OWL 语义闭包；其图是一般 QA graph。

SubgraphRAG：独立 triple scoring，不强制连通

ICLR 2025 · shortest-path weak supervision · directional distance encoding · 代码
同行评审开源

方法用 shortest path 产生弱监督标签，对每个 triple 独立预测 Bernoulli relevance；Directional Distance Encoding 分别沿正向/反向传播 query/topic entity 距离。最终直接取 top‑100 triples，不要求输出连通子图。

它对 G‑Retriever 的核心反驳是：答案所需的相关 triples 可以分散，强制一棵连通树可能为连接而引入大量无关边。

Systems & agentic retrieval

08 · 从固定检索器到会规划、反思和控制成本的 Agent

KAG：Schema-constrained KG + OpenIE graph + chunk 的复合系统

2024 · OpenSPG/KAG 官方代码
技术报告开源/源码核查全文深读

知识表示与检索

LLMFriSPG M={T,ρ,C,L} 同时维护强 schema 图 KG_cs、OpenIE fact graph KG_fr 与 raw chunks RC，并建立 graph↔chunk mutual index。实体标准化和 concept alignment 把自由抽取结果对齐到 schema。

Solver 把问题规划为 Retrieval / Sort / Math / Deduce / Output 等 logical-form operators；graph-first、chunk fallback 和 hybrid 可以按优先级执行，memory/judge/reflection 最多 3 轮。

公开实验

在 HotpotQA、2WikiMultiHopQA、MuSiQue 各抽 1k 问题，DeepSeek‑V2 下 KAG 的 EM/F1 分别为：

  • Hotpot：62.5 / 76.2
  • 2Wiki：67.8 / 76.2
  • MuSiQue：36.7 / 48.7

对照 IRCoT+HippoRAG 为 51.0/63.7、48.0/57.1、26.2/36.5。从 mutual index 到 alignment、LFS graph、hybrid，F1 逐层上升。

边界：KAG 是公开系统中 schema-aware planning 最完整的一类，但 SPG-Schema、KGDSL 和 OpenSPG property graph semantics 不等于 W3C OWL 2；论文 benchmark 仍是文档多跳 QA。

GraphRAG‑R1（WWW 2026）：用 GRPO 学何时继续检索

检索 token 不计入 LM loss；PRA 对连续正确检索给予递减增量奖励，CAF 用 F1 · a · exp(−bN) 惩罚过多调用。LoRA r=16、α=32，最多 8 次检索。

Hotpot/MuSiQue/2Wiki/PopQA F1 为 38.00/20.06/32.24/35.04；平均调用约 1.94/2.36/2.05/1.49。去掉 PRA 或 CAF 均降低 F1，说明 process reward 与成本 reward 分别控制搜索深度和效率。

GRIL：Retriever 与 Reader 联合适配

query-aware attention 对 head/neighbor/relation 打分，Gumbel-sigmoid 生成可微 mask；Complexity Assessment 预测 hop 数并分配 5 × complexity triples。subgraph 同时以 SAG soft graph token 和 verbalized triples 进入 LLM。

WebQSP/CWQ Hit/F1 为 86.8/73.0、68.3/60.5；MedQA 为 70.4。去掉 soft token 降至 66.1，去掉文本降至 64.8，显示结构 token 和可读证据互补。

HyperGraphPro / ProGraph‑R1：step-wise progress reward

结构分数将 semantic relevance 与 query-connected hyperedge 中的 entity distinctiveness 结合；progress reward 用加入当前证据前后 gold answer 概率差估计，另加 connectivity/answer overlap 结构奖励并做 step-wise GRPO。

Qwen2.5‑3B 平均 F1 54.56，对照 Graph‑R1 49.89；7B 为 59.38 vs 55.94。它代表“每一步检索是否推进答案”的前沿，但仍是 2026 预印本，结构奖励使用 answer label。

BYOKG‑RAG：Schema-aware tool routing

KG-Linker 生成 entity、candidate answer、relation paths 与 OpenCypher；实体用 fuzzy + BGE‑M3 top‑3 链接。Agent 可选择 relation BFS、Dijkstra path、OpenCypher 和 triplet retrieval 四类工具，最多迭代 2 次。

CWQ retrieval Recall@10：agentic 70.5、396 tokens；scoring 60.6、1,483 tokens。直接证明工具化 schema linker 可以在更少上下文下工作，但完整 schema 入 prompt 的规模假设较强。

Agentic 不等于 ontology-aware：奖励函数可以学到“多查一次是否提高答案概率”，却未必知道查询是否违反 domain/range、是否遗漏逻辑必需公理。过程控制和形式语义检查是两条正交技术线。

结构充分性

最短路径是否覆盖 gold relation chain、locality module 是否保留目标 entailment、schema card 是否覆盖 query plan 所需 domain/range。单看 node overlap 不足。

端到端但可归因

公开 benchmark 缺口：这批 2024—2026 工作中，尚未出现一个被广泛采用的数据集，同时包含自然语言问题、gold TBox signature、gold axiom/module、可执行 query plan、实例答案，并对 token/latency 做统一报告。

固定提交的源码级核查

Microsoft GraphRAG · 14a00ad8

mixed_context.py 用 entity embedding + oversampling 找实体，再在 token budget 中拼 community reports、entities、relationships、covariates 与 text units。Global Search 是 community reports 的 map/reduce；DRIFT 先用社区报告产生 primer 与 follow-up questions。图和摘要均来自文档抽取，不是可逆 OWL 索引。

LightRAG · bbebdd64

operate.py 先让 LLM 抽 high-/low-level keywords；低层检索 entity VDB，高层检索 relationship VDB，mix 再加入 chunk vector。一旦 entity 命中，会读取 node degree、一跳 edges 和关联 chunks。比单一 Top‑K 丰富，但结构扩展仍是一跳与权重启发式。

HippoRAG · e37fba2a

HippoRAG.py 中 fact embedding 决定候选，LLM filter 后 subject/object 形成 PPR seed；passage dense score 同时注入。add_fact_edges 主要建立 subject↔object 无向边，predicate 不作为传播节点，因此关系语义可能在扩散中丢失。

KAG · fdab15b3

Builder 同时支持 schema-free / schema-constrained extraction、实体标准化与 graph/chunk 双向索引。Hybrid executor 同优先级并发调用 retriever，合并后可在首个非空 graph/chunk/docs 停止。OpenSPG compose 含 Java、MySQL、Neo4j/APOC、MinIO，Java 最高 8GB heap，完整部署明显重于 demo。

Neo4j GraphRAG · 5a78f7e1

VectorCypherRetriever 在向量命中后执行开发者指定 traversal Cypher；Hybrid 合并向量与 full-text。Text2Cypher 可读取 schema/APOC 样例，生成后先 EXPLAIN 并检查只读；ToolsRetriever 允许 LLM 选择多个 retriever 后合并有来源结果。

Cognee · 325acf35

RDFLib resolver 能读 RDF/XML/Turtle/JSON-LD 等，索引 class 与 typed individual，并对 rdf:type、subClassOf 和 object-property assertion BFS。ingest 投影为 is_a，但未覆盖 blank node、reasoning、完整 literal/data-property round-trip。AgenticRetriever 采用渐进 skill loading，是上下文披露上的有用实现。

实现覆盖结论：目前没有一个开源项目同时完整覆盖“OWL 语义保持、自然语言锚点识别、向量召回、语义模块抽取、Agent 渐进式上下文、黑盒实例查询”。现有组件分别解决不同层。

Standards & formal semantics

12 · 不能由 GraphRAG 替代的标准与经典算法

OWL 2 Profiles

OWL 2 EL、QL、RL 在表达能力和推理复杂度之间选择不同边界。一个系统只有在明确保留哪些 axiom、采用何种 entailment regime 后，才能讨论“子图是否语义充分”。

SPARQL 1.1

提供可执行、可审计的 RDF 图查询中间表示。LLM 生成可被 parser、query planner 和 ontology validator 分阶段检查，而不必把最终答案完全交给自由文本推理。

SHACL

面向 graph shape 的 cardinality、datatype、class、path 等约束。ANCHOR 展示了“映射→验证报告→修复”的闭环；它不是开放世界 OWL reasoning 的替代品，但非常适合工具边界校验。

SKOS

preferred/alternative label、broader/narrower/related 等词汇语义为 terminology retrieval 提供标准表达。很多商业 taxonomy RAG 实际主要处理这一层。

RDF/OWL 原生工具的实际职责

Apache Jena / Fuseki

本体/RDF 数据的 SPARQL HTTP 服务、RDFS/OWL 推理、SHACL 验证和精确图模式查询；解决语义正确性与可查询性，不解决自然语言 seed ranking。

OWLAPI ModuleExtractor

公理 API、Manchester rendering、syntactic/semantic locality module 和 atomic decomposition；适合从 query anchors 产生语义模块。

ROBOT

extract 支持 STAR/TOP/BOT；reason 可用 ELK/HermiT/JFact；query、verify、report 适合可复现构建和 CI 检查。

Current research scope

13 · 当 ABox 尚未就绪或长期黑盒时，文献能说明什么

这一节只做研究边界归纳，不展开实施建议。

已经有较强证据的问题

  • 完整 ontology/chunk 顺序输入不能可靠替代 reasoner（DL‑Lite）。
  • schema domain/range 对 zero-shot relation composition 有显著作用（SG‑KBQA）。
  • 类链接与属性链接的难度和最佳路由不同（ANCHOR）。
  • ontology 可在生成后作为确定性查询检查器，而不只是 prompt（OBQC）。
  • 结构压缩与更大上下文之间并非单调关系（G‑Retriever 等）。
  • 图检索和文本/定义检索通常互补（KAG、ToG‑2、GRIL）。

仍未被现有研究回答的问题

  • 3GPP/电信规模 OWL 本体上，embedding seed + locality module 是否优于 k-hop/Steiner。
  • 对 class、relation、restriction 分别采用何种索引单位与 top‑k 才最稳定。
  • 最小充分 TBox context 是否能在黑盒查询协议变化时保持迁移性。
  • 没有可观测实例层时，怎样以 gold query plan/competency question 预测最终 QA 表现。
  • Agentic retrieval 的成本收益能否迁移到形式本体，而不破坏语义约束。
当前技术状态的最短描述：Embedding 仍是语言到本体候选的必要入口，但不是语义裁决器；图算法负责结构相关性，但不自动提供逻辑保证；OWL/SHACL 工具提供语义和验证，却不理解用户语言；Agent 的价值在于按需组合这些能力，而不是在参数中“掌握整个本体”。

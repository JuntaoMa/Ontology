结论
不要把“领域知识、意图路由、召回、精排”塞进同一个模型。

最稳妥的方案是四层解耦：24–150M 意图编码器 → 稠密+稀疏+本体别名的混合召回 → 100–300M 线上精排学生模型 → 4B 领域 LLM 做解释与约束推理。0.6B/4B 强模型主要承担教师、离线标注和质量上限。

执行摘要

先给决策，再给技术细节。以下数字是建议的项目门禁，不是任何模型在未知硬件上的无条件承诺。

领域主模型 Qwen3‑4B

中文、多语言与工具调用基础较合适；优先 RAG + QLoRA/RAFT，不从零预训练。

轻量意图 24–150M

分类/OOD 用编码器；自由文本改写若要求可靠，参数预算应放宽到 0.5–0.6B。

粗排目标 ≤ 50 ms

300–600M Embedding + 并行混合检索；验收同时看 Recall@50，不只看均值延迟。

精排目标 ≤ 30 ms

Top‑10/20、短序列、100–300M 交叉编码器或 late interaction；0.6B 生成式精排只做上限。

最需要避免的投入误区

把频繁变化的本体实例和规则“背进”4B 权重，会带来更新慢、来源不可追溯和遗忘问题。权重应学习领域语言、任务格式与推理习惯；事实、层级、约束和版本应保留在本体库与检索层。

检索链路追求确定性、可解释和低时延；LLM 放在后段处理需要语言生成与组合推理的部分。

为什么混合召回

语义、术语、标识符各有盲区

Dense 擅长释义，BM25/SPLADE 保留精确词项，IRI/别名通道保护编号、缩写和已知实体。RRF 用名次融合，避免直接混合不可比的原始分数。Qdrant 与 Milvus 均已原生支持混合检索与 RRF。S41

为什么保留图检索

关系不是向量相似度

父子类、等价、限制、前置条件、版本替代关系应通过 SPARQL/图遍历确定性获得。KG²RAG 的做法也是先语义找种子，再由知识图谱扩展并组织结果。S18

为什么 LLM 后置

把可验证步骤留在系统里

本体更新只重建图与索引，不重训模型；OntologyRAG 的实证动机同样是避免本体每次更新都重新训练，并保留可解释的映射证据。S17

需求约束与可行性修正

“内存”以下按 GPU 显存理解；若仅指 CPU RAM，3–6B 训练将严重依赖卸载并失去效率优势。

原始需求 可行性 需要增加的条件 修正后验收口径
3–6B 学习本体结构与知识；15–30G 可做 但只适合 PEFT/QLoRA 或分布式继续预训练 4B 起步；事实放 RAG/图库；序列长 2K–4K；gradient checkpointing；训练/推理显存分开预算 领域问答提升、结构化输出正确率、SPARQL 可执行率、证据忠实度；不以“模型背住多少三元组”为核心指标。

“保证召回”只能被定义为测试集上的可审计门禁

开放世界检索不存在无条件 100% 召回。必须限定本体版本、查询分布、ACL、索引规模、Top‑K、硬件和统计分位数；并为 OOD、歧义、无答案请求设计澄清/拒答路径。

04 / 13

2025–2026 技术版图

最新趋势不是单纯“模型更大”，而是更强的指令化表征、可裁剪维度、多路检索、教师蒸馏与面向文档的多模态检索。

Instruction-aware embeddings

同一个模型按任务指令改变表征空间

Qwen3 Embedding 提供 0.6B/4B/8B 系列、100+ 语言、32K 上下文、可自定义指令和 MRL 维度；模型卡报告多数下游任务使用指令可提升 1%–5%。S05S13

Small on-device encoders

300M 级模型重新成为低时延主力

EmbeddingGemma 308M 支持 100+ 语言和 128–768 维 MRL；Google 公布 EdgeTPU 单次嵌入低于 22ms、量化后 RAM 低于 200MB。该数字仅证明端侧可行性，不能直接外推到企业服务器。S07

Teacher → student ranking

强生成式教师，快编码器学生

Qwen3‑Reranker‑0.6B 在其模型卡的多项检索基准上明显领先旧 0.3–0.6B reranker；但线上 30ms 更适合 306M mGTE encoder 或进一步蒸馏。S06S12

Late interaction

单向量与全交叉编码器之间的中间层

ColBERTv2 保留 token 级向量并用 MaxSim 计算相关性，PLAID 通过质心剪枝把大规模检索压到几十毫秒；代价是更大的多向量索引和复杂工程。S49S50

Learned sparse retrieval

神经词项扩展补足 Dense 的精确匹配盲区

SPLADE‑v3 延续可解释稀疏表示，在 40+ 查询集的元分析中优于 BM25/SPLADE++；对英文更成熟。中文企业场景应先用 BM25 + 领域词典，再验证 BGE‑M3 sparse 或自训 SPLADE。S51

Ontology / KG guided RAG

语义召回提供种子，图关系提供连续上下文

OntologyRAG 与 KG²RAG 都强调利用本体/知识图谱的结构偏置；后者明确采用“语义种子 → KG 扩展 → 图组织”流程，适合本项目。S17S18

05 / 13

LLM 训练方案

4B 主模型学习领域语言与工作方式，轻量模型学习确定性路由；把“知识更新”留给本体和索引。

5.1 领域理解 LLM：推荐 Qwen3‑4B 起步

Qwen3‑4B 是 4.0B 参数、原生 32,768 上下文、支持 100+ 语言并提供 thinking / non‑thinking 切换的 Apache‑2.0 模型，符合中文企业场景、3–6B 规模和单卡部署的交集。 S01 S02 Gemma 3‑4B 可作为跨语言/多模态候选，但中文领域首轮不建议同时维护两条主模型训练线。

模型应该学什么
  • 领域术语、缩写、同义词与表达风格
  • 任务协议：JSON、SPARQL、工具调用、引用格式
  • 如何使用本体上下文、处理干扰文档与证据冲突
  • 澄清、拒答、置信度与升级人工的行为边界
  • 稳定的领域推理范式和少量长期基础知识
模型不应该独自承担什么
  • 频繁变动的本体实例、产品编码和业务状态
  • 必须逐条审计的法规、规则与资格条件
  • 租户 ACL 和文档权限判断
  • 可由 OWL / SHACL / SPARQL 确定性完成的逻辑
  • 没有来源的“补全式”事实生成

5.2 四阶段训练，而不是一次性 SFT

Stage 0
无训练基线：RAG + 结构化提示 + 工具

先得到零样本/少样本性能、错误类型与检索瓶颈。没有这个基线，无法证明训练的边际价值。

Stage 1
领域继续预训练 DAPT（有条件）

只在术语切分、领域句法、长文风格明显失配且有至少数亿高质量 token 时做。按文档/时间切分，混入通用回放数据，监控通用能力遗忘；不要对很小语料机械重复多轮。

Stage 2
SFT：让模型学任务协议

以真实任务为单位构造 1–5 万条高质量样本：意图解释、实体对齐、查询分解、SPARQL、证据引用、无答案与冲突处理。先追格式有效率和行为一致性。

Stage 3
RAFT：让模型在噪声检索中找对证据

每个问题同时提供正确证据和相似干扰文档，训练模型忽略 distractors、引用证据并回答。RAFT 原论文正是面向 in-domain open-book 场景。S16

Stage 4
偏好优化（仅在有明确偏好数据时）

对“更忠实、更简洁、更会澄清”等偏好做 DPO；不建议为了追赶技术潮流直接做 RL。TRL 已提供 SFT、DPO、GRPO 等标准实现。S34

15–30GB 显存的训练策略

首版采用 4‑bit QLoRA、LoRA 覆盖 all‑linear、BF16 计算、gradient checkpointing、2K–4K 序列。QLoRA 的核心是冻结 4‑bit 基座并只训练低秩适配器；其论文展示了 65B/48GB 的内存效率，因此 4B 在 24GB 单卡上有充足工程空间，但实际峰值仍取决于序列、batch 和优化器。S31S32

5.4 训练样本配比建议

真实任务 40–60%

日志、工单、搜索失败、专家问法；价值最高。

专家构造 15–25%

边界案例、反例、冲突、否定与复杂约束。

合成增强 20–40%

改写、难负例、长尾意图；必须抽检与去模板化。

通用回放 10–30%

用于继续预训练/SFT 的抗遗忘，比例需实验确定。

上述比例是工程起点而非学术定律。每次训练固定一份 sealed test set，并把数据版本、模板版本、教师模型、提示词和过滤规则写入 MLflow/DVC。

难负例优先级
  1. 结构难负例：同父类、兄弟类、逆关系、相邻但不满足约束的概念。
  2. 词法难负例：术语高度重合但语义不同，特别是否定、单位、阈值和版本。
  3. 语义难负例：旧 embedding Top‑K 中被专家判为 0/1 级相关的项。
  4. 权限难负例：内容相关但当前租户无权访问；用于系统测试，不直接当语义负例。

Hard negative 是领域微调成败的核心。NV‑Retriever 提出的 positive‑aware mining 用正例分数作锚点， 可过滤“其实也相关”的假负例；Sentence Transformers 已提供结合 bi‑encoder、CrossEncoder 和 FAISS 的挖掘接口。 S14 S15

6.4 三条可部署路线

Route A · 首选

Dense + BM25 + 小 Cross‑Encoder

工程最稳、可解释、易控制 Top‑K；最适合先验证 50/30ms。向量库使用 Qdrant/OpenSearch/Milvus 任一成熟平台。

Route B · 准确率增强

Dense + Sparse + Late Interaction

用 ColBERT/BGE‑M3 multi‑vector 代替或补充 cross‑encoder，延迟可控但索引体积与部署复杂度上升。

Route C · 质量上限

Dense + 0.6B 生成式 Reranker

适合低 QPS、离线批处理或高价值请求；不与 30ms 硬门禁同时作为首版目标。

07 / 13

企业语料如何高效整理

把语料工程视为有版本、有血缘、有权限的数据产品，而不是一次性“清洗后丢进向量库”。

7.1 四层数据产品

Bronze · 原始层

不可变原件

PDF、Office、网页、数据库快照、RDF/OWL、日志；保存 checksum、来源、owner、许可、ACL、抓取时间。

Silver · 规范层

结构化解析

统一成 Docling JSON/Markdown/Parquet；保留标题层级、页码、表头、坐标、语言和解析置信度。

Gold · 语义层

本体对齐

实体/关系/证据/路径卡；IRI、别名、断言与推断分离；SHACL 校验；细粒度 ACL。

Platinum · 任务层

可训练与可评测

意图标签、query‑doc、hard negatives、rerank 列表、SFT/RAFT、sealed test；完整记录生成配方。

7.2 标准流水线

盘点数据源、owner、权利、敏感级别、更新频率
解析版面、OCR、表格、公式、标题、锚点
清洗编码、噪声、页眉页脚、语言、PII、密钥
去重exact → MinHash/LSH → semantic
语义化本体对齐、实体卡、关系卡、证据卡
标注真实问题、正例、难负例、四级相关性
发布版本、数据卡、门禁、索引、回滚指针
文档解析策略

按文档类型路由，不用单一解析器吃所有格式

  • Born‑digital PDF / Office：Docling 标准 pipeline，保留 reading order、表格结构、公式与页锚点。S24
  • 扫描、复杂双栏、公式密集：Docling VLM 或 MinerU；关键文档做页级可视化抽检。MinerU 支持 PDF/Office、OCR、表格 HTML 和公式 LaTeX。S25
  • 结构化源优先走原生 API/数据库导出，避免“先打印成 PDF 再 OCR”。
去重策略

三级去重，且保留“同源版本”关系

  • Exact hash：去除字节/规范文本完全重复。
  • MinHash + LSH：发现轻微格式或编辑差异。
  • Embedding + clustering：识别转述、翻译和模板化重复；阈值必须抽样标定。
  • 法规/手册不同版本不是简单重复，应保留 isRevisionOf 与有效期。NeMo Curator 原生支持 exact、fuzzy 和 semantic 三类去重。S26

7.3 必须随每个 chunk 保存的元数据

维度 字段示例 为什么必须
身份与版本 document_id, version_id, chunk_id, checksum, valid_from, valid_to 增量重建、去重、回滚、时间点查询。
来源与血缘 source_uri, owner, primary_source, derived_from, parser_version, generated_by 引用、审计和重现；可用 W3C PROV‑O 的 Entity / Activity / Agent 表达。S23
定位 title_path, page, paragraph, bbox, table_id, row_id 回答可回到原文；表格和扫描件可做视觉复核。

质量 parse_confidence, ocr_cer, table_score, dedup_cluster, reviewer, review_status 低质量内容可降权或隔离；支持后续重解析。

7.4 本体感知切分规则

原子优先

定义和约束不跨块

一个类定义、一个关系说明、一个业务规则、一个表格行组尽量保持完整。固定 512 token 滑窗只能做兜底。

多粒度

实体 / 段落 / 文档三级索引

短 query 先命中实体卡，再向父文档扩展证据；全局问题走章节/社区摘要，不让超长块挤占 reranker。

表格语义

行必须携带表头和章节路径

将“阈值 30”重写为“严重高温停机阈值：30 分钟”，同时保留原表格坐标，避免脱离表头后失义。

合成数据不是廉价真值

LLM 可以生成改写、问题和候选负例，但不能直接决定事实正确性。本体断言用规则/推理器验证，检索相关性用专家抽检与分歧仲裁；合成样本必须记录教师模型、提示、温度和生成时间。

语料与标注质量要求

质量门槛分为“不可妥协的合规/血缘门禁”和“需要在项目中校准的统计门禁”。

8.1 建议验收门禁

层级 指标 建议门槛 说明
来源 / 权利 可追溯率、owner/许可/ACL 完整率 100% 任何缺来源或不明权利内容不得进入 Gold/Platinum；每个数据集配 Datasheet/Data Card。S47S48
解析 关键文档页级通过率 ≥ 98% 抽检标题层级、阅读顺序、页码和表格；扫描文档单独报告字符错误率 CER，不能与原生 PDF 混算。
本体 严重 SHACL violation / 不可满足类 0 SHACL 用形状图验证 RDF 数据图；发布前阻断 severity=Violation。S20
去重 精确重复；近重复误删率 精确重复 0；误删 < 1% 语义去重阈值通过成对抽检标定；版本文档保留而非删除。
意图标注 双标一致性 Krippendorff α / Cohen κ ≥ 0.80（建议） 低于门槛先修标签定义和边界案例，不急于训练；所有分歧由第三位专家裁决。
检索标注 每 query 正例、难负例、相关性等级 ≥ 1 正例；4–15 难负例；0/1/2/3 四级 必须包含 sibling、旧版本、否定、数值阈值、关系方向和词法高度相似项。
测试集 query 数与泄漏 首版 1,500–3,000；家族级零泄漏 同一原问题的改写、同一文档版本、模板生成簇不能跨 train/test；建议增加时间外推集。
安全 密钥/PII/越权检索 严重泄漏 0 权限过滤在检索前执行；数据治理对齐组织风险框架并保留人工审查。NIST AI RMF GenAI Profile 可作过程参考。S46

98%、0.80、1,500–3,000 等是本报告给出的工程建议门槛，不是外部标准的强制值；应根据业务风险、标注成本和置信区间校准。

8.2 一份合格的检索金标要覆盖什么

表达变化
  • 缩写、别名、口语、错别字、混合中英文
  • 同义改写、长问句、关键词式查询
  • 否定、反事实、比较、数值和单位
本体结构
  • 父子类、兄弟类、等价类、逆关系
  • 1–2 hop、多约束交集、domain/range
  • 废弃概念、版本迁移、断言与推断
系统边界
  • 无答案、信息不足、必须澄清
  • 有内容但无权限、租户隔离
  • 多个同等正确答案与冲突来源

8.3 防止数据泄漏

  1. 先封测试集，再做教师合成。任何用于提示、few-shot、hard-negative 挖掘或超参选择的 query 都不再是测试集。
  2. 按 query family / source family / version group 切分。不能随机拆分同一个问题的十个改写。
  3. 设时间外推集。训练只见旧本体版本，用最新版本检验系统能否通过检索更新而非依靠权重记忆。
  4. 评测集只存稳定 ID。答案指向 ontology IRI、document version 与 span；避免只存可漂移的自由文本答案。

显存与时延预算

权重大小可计算，真实峰值取决于框架、上下文、batch、KV cache 和量化内核；以下用于容量规划与压测起点。

10.1 模型内存估算

模型 / 模式 仅权重理论值 建议规划值 15–30GB 可行性 备注
4B BF16 推理 约 8GB 10–16GB 可行 规划值含运行时、短上下文 KV 与碎片；长上下文/并发会继续增加。
4B INT4 推理 约 2GB 4–8GB 宽裕 量化质量与实际加速依赖硬件内核；必须回归领域任务。
4B QLoRA 训练 基座约 2–3GB 14–24GB @ 2K–4K 首选 含适配器、梯度、激活与优化器的经验规划；gradient checkpointing 必开。

24–150M encoder FP32 0.1–0.6GB 0.4–1.5GB 满足 2.5GB INT8 后更低；CPU 也可部署，GPU 可把延迟压至数毫秒级。

10.2 在线延迟预算

阶段 目标 p95 执行方式 关键控制变量
权限与规范化 1–3ms CPU ACL bitmap / filter cache；不访问慢外部系统。
意图 / OOD 3–8ms 24–150M encoder，CPU INT8 或 GPU query ≤ 128 tokens；与检索准备并行。
Query Embedding 10–30ms 300–600M，FP16/INT8，GPU 常驻 短 query、无冷启动、动态 padding；MRL 主要省索引/搜索，不必然大幅减少 encoder 前向。
ANN + BM25/Sparse + Exact 8–18ms 三路并行 索引规模、HNSW ef、过滤选择性、shard、Top‑K；RRF 只融名次。
图扩展与融合 3–10ms 本地缓存 + 受限 SPARQL 只做 1–2 hop、关系白名单、路径上限、预计算高频路径。
Rerank Top‑10/20 15–30ms 100–300M encoder，FP16/INT8 总长 ≤ 192–256、unpadding、GPU 常驻；Top‑K 是最大杠杆。
检索端到端（不含生成） 45–80ms 意图与多路召回并行 若 50ms 是全链路硬 SLA，需要进一步缩小模型、Top‑K 或将 rerank 变成 late interaction。

动态 batching 的目标是吞吐，不等同于低时延

Triton 支持将请求合并成动态 batch，并允许设置最大排队等待；应从 0 延迟开始调，只有 p95 仍在预算内才增加 queue delay。S39 ONNX Runtime 的 INT8/INT4、图优化和 Transformer optimizer 可用于 CPU/边缘学生模型，但量化可能在旧硬件上反而变慢，必须实测。S40

10.3 压测矩阵必须固定

硬件

CPU 型号 / 核数、GPU 型号、显存、CUDA/驱动、NUMA、磁盘与网络。

负载

并发 1/8/32/64；冷/热；短/中/长 query；Top‑K 10/20/50。

数据

索引 10万/100万/1000万；向量维度；过滤选择性；分片与副本。

报告

p50/p95/p99、QPS、GPU 利用率、队列时间、tokenize/forward/search 分解。

11.2 建议上线门禁

门禁 建议目标 阻断条件
意图路由 Macro‑F1 ≥ 0.90；关键意图 Recall ≥ 0.95；ECE ≤ 0.05 任何高风险意图 Recall 明显低于基线或 OOD 被强制路由。

安全 越权内容召回 = 0；严重敏感信息泄漏 = 0 ACL 只在 LLM 输出层过滤；任何跨租户候选进入 reranker。

具体阈值应在首轮基线后由业务风险委员会确认。通用检索基准可参考 BEIR/MTEB，但生产门禁必须来自企业自建金标；Qwen、EmbeddingGemma 等模型卡的排行榜只用于候选筛选。

11.3 线上闭环

记录query、候选 ID、分数、版本、耗时
反馈点击、改选、复制、人工纠错、零结果
采样低置信度、模型分歧、长尾、高价值
专家标注双标、仲裁、来源检查
回归sealed test + 最新时间集 + 安全集
灰度shadow → 5% → 25% → 100% + 回滚

16 周分阶段路线图

先证明检索价值，再训练模型；每阶段都有可停、可回退的验收点。

第 1–2 周
定义任务、数据合同与基线

冻结意图 taxonomy、本体版本、Top‑K、硬件与 SLA；盘点数据权利/ACL；构建 300–500 条 pilot 金标；跑 BM25、通用 embedding 和无训练 LLM‑RAG。

第 3–5 周
语料与本体索引 MVP

建立 Bronze/Silver/Gold；Docling/MinerU 路由；实体/关系/证据卡；SHACL 门禁；Qdrant/OpenSearch + Fuseki；完成 Dense+BM25+IRI 三路召回。

第 6–8 周
Embedding A/B 与金标扩充

比较 EmbeddingGemma、Qwen3‑Embedding‑0.6B、现有模型；构造 1,500–3,000 query 金标；正例感知 hard negatives；完成领域 embedding 微调和 p95 压测。

第 9–11 周
意图模型与 Reranker 蒸馏

24–150M 意图模型、OOD 与校准；Qwen3 reranker 教师标注；306M/更小学生训练；Top‑K/长度/量化消融；达成 50/30ms 的条件化结论。

第 12–14 周
4B LLM SFT / RAFT

先 SFT 任务协议，再用真实召回候选做 RAFT；只有 Stage 0 显示明显领域语言失配时才加入 DAPT；验证证据忠实度、SPARQL 和拒答。

第 15–16 周
安全、灰度与运行手册

越权/注入/回滚演练；shadow 流量；5% 灰度；建立每日质量看板、月度数据刷新、季度模型评估与本体变更触发器。

阶段决策闸门

Gate A · 第 5 周

先确认问题是不是检索

如果混合检索已解决大部分错误，延后 4B 训练；资源转向语料、本体和难负例。

Gate B · 第 11 周

30ms 与质量能否同时成立

若 306M reranker 不达标，选择更小蒸馏、Top‑K 降低或 late interaction；不要默默放宽 SLA。

Gate C · 第 14 周

训练是否有可证边际收益

只有 SFT/RAFT 在 sealed test 上显著优于提示基线且不破坏安全/通用能力，才进入灰度。

最小团队配置

角色 建议投入 主要责任
本体 / 领域专家 1–2 FTE taxonomy、SHACL、金标、难负例、冲突仲裁、业务验收。
数据工程 1–2 FTE 采集、解析、血缘、版本、权限、数据卡、增量发布。

最终推荐的一句话版本

用 Qwen3‑4B + QLoRA/RAFT 做后段领域理解，用 24–150M encoder 做意图/OOD，用 EmbeddingGemma 300M 与 Qwen3‑Embedding‑0.6B 做速度/质量双基线，用 Qwen3 Reranker 当教师蒸馏到 100–300M 线上学生，并以 Dense + BM25/Sparse + IRI/别名 + 受限图扩展作为本体检索主干。
